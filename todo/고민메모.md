# 고민 메모 (racingcar)

## 1. 랜덤값 테스트
- 진짜 `Random`은 값 예측 불가 → 테스트 더블로 고정값 주입
- `RandomGenerator` 상속해 `generateNumber()`가 고정값 반환
- 경계값으로 검증: `MOVE_THRESHOLD`(전진), `MOVE_THRESHOLD - 1`(정지)

## 2. assert에서 getter 체이닝
- `car.getPosition().getPosition()`은 디미터 법칙 위반(내부 2겹 노출)
- Position은 값 객체 → `equals`/`hashCode` 구현 후 `isEqualTo(new Position(1))`
- equals만 재정의하면 안 됨: 규약상 hashCode도 같이 (HashSet/HashMap에서 깨짐)

## 3. private 메서드 테스트 고민 (핵심)
- "테스트 위해 private→public 여는 게 아쉽다"는 **설계 신호**
- 접근제어자를 바꾸는 게 아니라, **로직이 제자리에 없는 것**
- `createCars`는 도메인 규칙인데 Application(main)에 박혀 있음 → 도메인으로 이동

## 4. 일급 컬렉션
- 정의: 인스턴스 필드가 **컬렉션 딱 하나뿐**인 클래스
- `RacingCar`는 `cars` + `attemptCount` 2개 필드 → 일급 컬렉션 아님
- `Cars`로 분리 (필드는 `List<Car>` 하나) → RacingCar가 품어서 사용
- 효과: 생성/이동/위치수집 로직 응집, RacingCar의 for문 제거, 테스트 쉬워짐
